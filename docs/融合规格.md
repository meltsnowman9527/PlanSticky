## 0. 全局骨架

### 0.1 数据源与状态
单页应用，唯一数据源是 `GET /api/state`，返回：

| 字段 | 类型 | 说明 |
|---|---|---|
| `transactions` | 数组 | 每项 `{id, date, amount, type, category, purpose, note, createdAt}`，后端按 `date DESC, id DESC` 排序 |
| `budget` | 数字 | 默认 5000 |
| `theme` | 字符串 | `light` / `dark`，默认 `light` |
| `dataPath` | 字符串 | 数据库绝对路径，界面未使用 |
| `checkins` | 数组 | `{date, activity, detail, updatedAt}`，按 `date DESC` |
| `checkinTags` | 数组 | `{name, color}`，按 `sort_order, name` 排序 |
| `journals` | 数组 | `{date, content, format, updatedAt}`，按 `date DESC` |

前端全局状态（重写时应等价持有）：`selectedCategory`（默认「餐饮」）、`selectedType`（默认 `expense`）、`editingId`（null=新增）、`trendRange`（默认 7）、`calendarMonth`（默认当月 `YYYY-MM`）、`selectedCheckinDate`（默认今天）、`selectedActivity`（默认空串）、`savedJournalRange`（日记编辑器插入位置）。

所有写操作成功后都是「重新拉取 `/api/state` → 全量重渲染」的模式（`load()` → `render()`），不做增量更新。重写时可保留这一简单模型。

### 0.2 日期/金额基础口径
- 本地日期字符串统一 `YYYY-MM-DD`，月份 `YYYY-MM`。默认值均取**本机今天**。
- 金额格式：`Intl.NumberFormat("zh-CN", {style:"currency", currency:"CNY"})`，例如 `¥1,234.00`；表格中由前端额外拼接正负号（见 1.4）。
- 所有“支出”判定为 `type !== "income"`；即除 `income` 外一切类型都算支出。

### 0.3 页面切换与顶部导航
- 顶部固定栏（高 72px，底部 1px 分隔线，白/卡片底），左侧品牌区：绿色圆角方块「清」（衬线体）+ 粗体「清楚账本」+ 小字「本地数据 · 安心记账」。
- 中部徽标式分段导航（两枚按钮，选中态为白底绿字）：`账本`、`每日生活`。
- 右侧：主题切换按钮（圆形图标按钮）、主按钮 `＋ 记一笔`。
- 切换行为：
  - 账本页显示所有 `.page-ledger` 区块、隐藏 `.page-daily`；每日生活页反之（隐藏用 `display:none !important`）。
  - 每日生活页**隐藏** `＋ 记一笔` 按钮（记账表单只能在账本页打开）。
  - 切换后 `window.scrollTo(top, smooth)` 回到顶部。
  - 窗口标题：账本页 `清楚账本`；每日生活页 `每日生活 · 清楚账本`。
  - 选中页写入 `localStorage["qingchu-active-page"]`，下次启动恢复（只认 `daily`，其它一律 `ledger`）。
  - 导航按钮的 `active` 类同步。
- 区块英文小标题（全大写、字距 0.18em、绿色）：`QUICK ENTRY`、`MONTHLY OVERVIEW`、`SPENDING TREND`、`CATEGORY MIX`、`DAILY LIFE`、`DAILY CHECK-IN`、`DAILY JOURNAL`、`JOURNAL ARCHIVE`、`TRANSACTIONS`、`JOURNAL`（日记查看器内）。
- 主容器最大宽 1280px，居中，内边距 24px。
- 卡片通用样式：卡片底 `--card`、1px `--line` 边框、圆角 17px、阴影 `0 12px 36px rgba(28,66,49,.08)`。

### 0.4 主题 light / dark
- 实现方式：`<html data-theme="light|dark">`，由 CSS 变量切换。
  - light：`--bg:#f4f7f5`、`--card:#fff`、`--text:#18251f`、`--muted:#718078`、`--line:#e3eae6`、`--green:#176b4d`、`--soft:#e9f4ee`、`--danger:#c64136`、`--shadow:0 12px 36px rgba(28,66,49,.08)`。
  - dark：`--bg:#101713`、`--card:#18221d`、`--text:#edf5f0`、`--muted:#91a399`、`--line:#2b3a32`、`--green:#4dbe8f`、`--soft:#1f392e`、`--shadow:0 14px 40px rgba(0,0,0,.25)`。
- 切换按钮文字：当前 dark 显示 `☀`，当前 light 显示 `◐`。点击即取反，并 `PATCH /api/settings {theme}` 持久化到服务端 settings 表（不是 localStorage）。
- 主题在首次 `/api/state` 返回后才应用（重写时可先读本地缓存避免闪白，规格层面无要求）。
- 窄屏（≤750px）时主题按钮被隐藏；≤750px 时「账本/每日生活」导航变为底部固定栏（重写桌面端可忽略）。

### 0.5 Toast 提示
- 单一 Toast 元素，固定于底部居中（距底 25px），深色底 `#17251e`、白字、圆角 10px、字号 12px、`z-index:30`。
- 文案规则：**统一加前缀 `✓ `**，例如 `✓ 账目已删除`。
- 显示时长 **2200ms** 后自动隐藏。
- 触发场景全清单（共 18 处）：
  1. `✓ 请选择标签或写下今日心情`（签到保存前本地校验失败）
  2. `✓ 签到已保存`
  3. `✓ 签到已删除`
  4. `✓ 新标签已添加`
  5. `✓ 账目已删除`
  6. `✓ {文件名} 不是支持的图片格式`
  7. `✓ {文件名} 超过 20 MB`
  8. `✓ 已插入 {n} 张图片，可继续编辑`（n=本次所选文件数）
  9. `✓ 仅支持 MP4、WebM 和 MOV 视频`
  10. `✓ 单个视频最大为 300 MB`
  11. `✓ 视频已插入，可继续编辑`
  12. `✓ 请先写下日记内容`
  13. `✓ 日记已保存`
  14. `✓ 日记已删除`
  15. `✓ 已记下一笔，可继续添加`
  16. `✓ 账目已更新`
  17. `✓ 已导入 {inserted} 笔账目`
  18. `✓ 已恢复 {inserted} 笔账目`

### 0.6 确认框与报错框（原生）
- `confirm()` 文案：
  - `确定删除这笔账目吗？`
  - `确定删除这一天的签到吗？`
  - `确定删除这一天的日记吗？`
- `alert()` 文案：
  - `启动失败：{错误信息}`（初始化 `/api/state` 失败时）
  - `图片上传失败：{错误信息}`
  - `视频上传失败：{错误信息}`
- **重要边界**：除上述三处外，所有 API 失败都是未捕获的 Promise 异常 —— 界面上**没有任何可见提示**（如：添加重复标签触发 409「标签已存在」、日记内容全为 `<br>` 触发 400「日记内容不能为空」、CSV 导入后服务端逐行校验失败等）。重写时应补上统一错误提示（建议复用 Toast，前缀改为 `✕`，不自动缩短时长）。

## 1. 账本页（ledger）

### 1.1 记账表单

**显示/隐藏**
- 初始隐藏。点顶部 `＋ 记一笔` → 打开并**重置**为新增态（日期=今天、金额空、类型=支出、分类=餐饮、用途空、备注空）。
- 表单标题：新增态 `今天花了什么？`；编辑态 `修改这笔账`。
- 表单副标题固定：`数据只保存在这台电脑中。`
- 右上角关闭按钮 `×` → 与「取消」等效，直接隐藏，**无二次确认**（编辑态未保存的修改丢失）。
- 打开时平滑滚动到表单位置（`scrollIntoView({behavior:"smooth"})`）。

**字段**

| 顺序 | 字段 | 控件 | 属性/限制 | 占位符 | 必填 |
|---|---|---|---|---|---|
| 1 | 日期 | 日期选择器 | `type=date`，默认今天 | — | 是（HTML required） |
| 2 | 金额（元） | 数字框，左侧固定绿色 `¥` 前缀 | `type=number`，`min=0.01`，`step=0.01` | `0.00` | 是 |
| 3 | 类型 | 两段式切换（支出 / 收入） | 互斥高亮 | — | 是（必有值） |
| 4 | 用途 | 文本框 | `maxlength=40` | `例如：午餐、地铁月卡` | 是 |
| 5 | 备注 | 文本框 | `maxlength=100` | `可选` | 否 |
| 6 | 分类 | 8 宫格按钮 | 单选，详见下 | — | 是（默认「餐饮」） |

- 字段区布局：宽屏 5 列网格（日期、金额、类型、用途、备注同一行）；≤1050px 3 列；≤750px 2 列；≤560px 1 列。
- 用途/备注在提交前 `trim()`；日期、金额原样取（金额 `Number()`）。

**收入/支出切换**
- 两枚按钮：`支出`、`收入`，左侧支出右侧收入，中间 1px 分隔线，普通态卡片底+灰字。
- 选中支出：底色 `#c64136`（红），白字；选中收入：底色 `#176b4d`（绿），白字。
- 默认选中「支出」。编辑已有账目时选中该账目的类型。

**分类网格（8 个，固定顺序）**

| 序 | 名称 | 图标字符 | 颜色 |
|---|---|---|---|
| 1 | 餐饮 | 餐 | `#f59e0b` |
| 2 | 交通 | 行 | `#3b82f6` |
| 3 | 购物 | 购 | `#ec4899` |
| 4 | 居住 | 居 | `#8b5cf6` |
| 5 | 娱乐 | 乐 | `#14b8a6` |
| 6 | 医疗 | 医 | `#ef4444` |
| 7 | 学习 | 学 | `#6366f1` |
| 8 | 其他 | 其 | `#64748b` |

- 每个按钮 = 28×28 圆角 7px 的色块（内含白色单字图标）+ 分类名。
- 选中态：底色 `--soft`（浅绿）、文字与边框 `--green`、加粗。
- 宽屏 8 列，≤1050px / ≤750px 4 列，≤560px 2 列（左对齐）。
- 分类字段用 `<fieldset><legend>分类</legend>`，图例文字 `分类`。
- 后端只接受这 8 个分类名，其它值报「分类无效」。

**提交（保存账目）行为**
- 新增态：`POST /api/transactions`，成功后**不关闭表单**，只清空金额/用途/备注，日期/类型/分类保留，焦点回到金额框，Toast `✓ 已记下一笔，可继续添加`（便于连续记账）。
- 编辑态：`PATCH /api/transactions/{id}`，成功后**关闭表单**，Toast `✓ 账目已更新`。
- 请求体固定字段：`{date, amount(Number), type, category, purpose(trim), note(trim)}`。
- 表单校验由 HTML5 完成（required / min=0.01），不满足时浏览器拦截，不发请求，并给出浏览器原生提示。
- 编辑态保存后 `editingId` 归 null。

**进入编辑态的流程**
- 在明细表某行点 `编辑` → 用该账目对象填充表单（含 `editingId`），标题变为「修改这笔账」，展开并平滑滚动过去。
- **新增态与编辑态的唯一差别**：标题文案、是否预填、保存后是否关闭、以及请求方法与 URL（POST vs PATCH）。表单字段与校验完全一致。

**取消/关闭**
- `取消`（幽灵按钮，右对齐）与 `×` 均执行同一操作：隐藏表单、`editingId=null`。不提示、不保存。
- 表单底部操作条：右侧依次为 `取消`、`保存账目`（绿色主按钮，白字加粗）。

### 1.2 月度概览

**月份选择器**
- 位于「MONTHLY OVERVIEW / 月度概览」标题行右侧，`type=month`，初始值为当月；宽屏靠右自动宽度。
- 变更（`change` 事件，即选定后）立刻触发全量重渲染。
- 该值同时驱动：本月支出统计卡、日均、最高单笔、预算进度、环形图与分类列表、以及**明细表的月份过滤（仅当未使用日期范围时）**。
- 边界：若用户清空月份输入，则 `startsWith("")` 命中全部账目 → 统计变成全量；同时“天数”计算得到 `NaN`，日均显示 `¥0.00`、提示语变成 `按 NaN 天计算，收入 …`。重写时应对“未选择月份”做明确处理。

**统计卡片（3 张，宽屏列宽比 1.25 : 1 : 1，高度 ≥142px）**

卡片 1（主卡，整卡可为块级）：
- 顶部左侧 `本月支出`，右侧笔数 `{n} 笔`。
- **注意口径**：`n` = 该月**全部账目数（含收入）**，而金额只算支出。
- 中间大号金额（31px）`¥x,xxx.xx`。
- 下一行左侧 `月预算` + 内嵌数字框（`type=number`，`min=1`，宽 85px，无占位符，值来自 `settings.budget`）；右侧百分比 `{rate}%`。
- 进度条：高 6px 圆角槽（`--line`），填充绿色，宽度 = `min(rate,100)%`。
  - `rate = round(支出合计 / 预算 * 100)`，**可为负/超 100**；预算为 0 时 rate=0。
  - 预算输入变更时：`data.budget = max(1, Number(值) || 5000)` → `PATCH /api/settings {budget}` → 重渲染（重渲染会把输入框值覆盖回 `data.budget`）。
- 主金额下无其它说明文字。

卡片 2（日均支出）：
- 左侧 44×44 圆角徽章，蓝底浅蓝字 `日`（`#e8f1ff` / `#3978d2`）。
- 标题 `日均支出`，金额（23px）`¥x,xxx.xx`，第三行提示。
- 计算：`日均 = 本月支出合计 / days`；`days` 取值规则 = **若所选月份等于当前月，则取今天在本月的日号（1..31）；否则取该月的自然总天数**。
- 提示文案：初始静态 `按已过天数计算`；渲染后变为 `按 {days} 天计算，收入 ¥{本月收入合计}`（收入合计含全部 `type=income` 的当月账目）。
- 无支出时金额显示 `¥0.00`（天数照算）。

卡片 3（最高单笔）：
- 左侧 44×44 徽章，琥珀底棕字 `高`（`#fff0dc` / `#d27718`）。
- 标题 `最高单笔`，金额（23px）`¥x,xxx.xx`；无支出记录时显示 `¥0.00`。
- 提示文案：有记录时为**该笔账目的「用途」原文**；无记录时 `暂无记录`。
- 计算：仅在本月**支出**账目里按金额降序取第一条（不看收入，不按月以外范围）。

### 1.3 筛选与明细表

**筛选控件（同一行，右对齐）**

| 控件 | 类型 | 默认 | 占位/选项 |
|---|---|---|---|
| 搜索 | 文本框（宽 170px） | 空 | 占位 `搜索用途或备注` |
| 分类 | 下拉（宽 90px） | `全部` | 选项：`全部` + 8 个分类名，顺序同 1.1 |
| 类型 | 下拉（宽 80px） | `全部` | `全部` / `支出` / `收入`（value 分别 all/expense/income） |
| 开始日期 | 日期框（宽 130px） | 空 | 悬停提示 `开始日期` |
| 结束日期 | 日期框（宽 130px） | 空 | 悬停提示 `结束日期` |
| 分隔符 | 静态文本 | `~` | 位于两个日期框之间 |

**组合规则（按代码顺序）**
1. 日期过滤（二选一，互斥）：
   - 若「开始日期」或「结束日期」任一非空 → 使用日期范围，**完全忽略月份选择器**；`date < 开始` 或 `date > 结束` 的账目剔除（字符串比较，闭区间）。
   - 否则 → 只保留 `date` 以所选月份 `YYYY-MM` **开头**的账目。
2. 类型：`type` 必须等于所选值（`all` 时不过滤）。
3. 分类：名称必须等于所选值（`全部` 时不过滤）。
4. 关键词：将 `"{用途} {备注}"` 转小写后 `includes(搜索词.toLowerCase())`；搜索词先 `trim()`。**只匹配用途与备注两个字段**，不匹配分类、日期、金额。空搜索词不过滤。
5. 排序：`date` 降序；同日内 `id` 降序（新记录在前）。
6. 触发时机：每个筛选控件在 `change`/`input` 时立即全量重渲染（搜索为逐字符实时过滤）。

**结果计数**
- 标题行 `账目明细` 后跟一枚浅绿药丸标签，显示**当前筛选结果的条数**（数字，无单位，初始 0）。

**表格**
- 表头列：`日期`、`分类`、`用途`、`备注`、`金额`、空列（操作）。
- 行内容：
  - 日期：`YYYY-MM-DD` 原样。
  - 分类：小色块图标（28×28，圆角 7px，分类色 + 白字）+ 分类名；**若分类名不存在于 8 个分类中，回退为「其他」的图标与颜色**（但名称仍显示原值）。
  - 用途：加粗；HTML 转义。
  - 备注：灰色；为空时显示 `—`；HTML 转义。
  - 金额：加粗，收入前缀 `+` 且绿色（`--green`），支出前缀 `-` 且红色（`--danger`），数值为 `money.format(amount)`，例如 `-¥28.50`。
- 操作列：右对齐两枚小按钮 `编辑`（浅绿底绿字）、`删除`（浅红底红字 `#fff0ee` / `--danger`）。
- 删除交互：点击 → `confirm("确定删除这笔账目吗？")` → 确认后 `DELETE /api/transactions/{id}` → 重新拉取 → Toast `✓ 账目已删除`。
- 表格整体包裹在圆角卡片内，表头背景 `--bg` 灰色小字（字距 0.08em），行间 1px 分隔线，单元格内边距 12px/15px。
- ≤560px 时表格转为卡片式列表（每行一块，通过 `::before` 显示 日期/分类/用途/备注/金额/操作 标签），属移动端适配，桌面重写可忽略。

**空态**
- 当筛选结果为 0 条时，表格下方（表格容器内）显示空状态块，最小高 220px，垂直水平居中：
  - 圆形浅绿徽章内衬线体大字 `账`（46px 圆）；
  - 粗体 `这里还空着`；
  - 小字 `记下第一笔支出，图表会自动生成。`
- 空态与筛选无结果**共用同一文案**（不会区分“还没有数据”和“筛选无匹配”）。

### 1.4 CSV 导入 / 导出

**导出**
- 按钮 `导出 CSV` → 浏览器直接跳转 `GET /api/export.csv`（相当于下载）。
- 服务端响应：文件名 `qingchu-ledger-{YYYY-MM-DD}.csv`，`Content-Type: text/csv; charset=utf-8`，内容以 **UTF-8 BOM（`\uFEFF`）** 开头。
- 列（表头，中文）：`日期`、`金额`、`类型`、`分类`、`用途`、`备注`。
- 数据范围：**全部账目**（不受任何筛选影响），排序 `date DESC, id DESC`。
- 类型列写的是**原始英文值** `expense` / `income`（这正是导入兼容性的坑，见下）。

**导入**
- 按钮 `导入 CSV` → 打开文件选择（`accept=".csv"`，隐藏 input）。
- 解析规则：
  - 读取纯文本，**先去掉开头 BOM**（`replace(/^\uFEFF/,"")`）。
  - 使用自写的 CSV 解析器：支持双引号包裹的字段、字段内 `""` 转义为 `"`、引号内的逗号与换行；`\r\n` 与 `\n`、`\r` 均视为换行；**整行为空的行被丢弃**（只有全部单元格为空才算空行）。
  - **直接丢弃第 1 行（表头），不校验表头内容**——若文件没有表头，会丢失第一条记录。
  - 按列数判定格式：
    - 列数 ≥ 6 → 新格式：`日期, 金额, 类型, 分类, 用途, 备注`；类型 `=== "收入"` 映射为 `income`，**其它任何值（包括导出产生的 `income`）都映射为 `expense`**；分类为空时取 `其他`；用途/备注为空时取空串。
    - 列数 = 5（或其它 <6）→ 旧格式：`日期, 金额, 分类, 用途, 备注`，类型固定 `expense`；分类为空取 `其他`。
  - 金额 = `Number(第2列)`（非法则为 `NaN`）；日期原样字符串。
  - 前端不做任何校验，整批 `POST /api/import {transactions: rows}`。
- 服务端 `/api/import` 行为：逐行调用 `validate()`，**只插入通过校验的行，不通过的行静默丢弃**；返回 `{inserted: n}`。导入是**纯追加合并**，不做去重、不覆盖、不按 id 匹配。
- 成功后：重新拉取数据 → Toast `✓ 已导入 {inserted} 笔账目`。文件输入值被清空（可重复导入同一文件）。
- 未处理的情况（重写建议补齐提示）：文件读取失败、JSON 解析失败、`inserted` 为 0 时仍提示“已导入 0 笔账目”、因导出/导入类型映射不一致导致**收入在往返后变成支出**。
- 编码：只按 UTF-8 解析（`file.text()`）；GBK CSV 会乱码。

### 1.5 备份 / 恢复

**备份（导出）**
- 按钮 `备份` → 纯前端生成文件，**不发请求**：把内存中的整个 `data`（即 `/api/state` 的完整响应）以 `JSON.stringify(data, null, 2)` 序列化。
- 文件名：`清楚账本备份-{YYYY-MM-DD}.json`；MIME `application/json`。
- 因此备份内容包含：`transactions`、`budget`、`theme`、`dataPath`、`checkins`、`checkinTags`、`journals`（**含全部日记 HTML 与签到记录**）。

**恢复（导入）**
- 按钮 `恢复` → 文件选择（`accept=".json"`）。
- 解析：`JSON.parse` → 仅校验 `Array.isArray(parsed.transactions)`；不满足时抛出 `备份文件格式无效`（该错误**没有任何 UI 呈现**）。
- 行为：把 `parsed.transactions` 交给 `POST /api/import`，即**逐行校验后追加插入（合并，绝不清空/覆盖）**；重复恢复同一备份会产生重复账目。
- 备份中的 `budget`、`theme`、`checkins`、`checkinTags`、`journals` **在恢复时被完全忽略**（不还原预算、主题、签到与日记）。
- 成功后重新拉取 → Toast `✓ 已恢复 {inserted} 笔账目`，清空文件输入。

## 2. 图表

### 2.1 趋势图（trend）

**控件**
- 标题：小标题 `SPENDING TREND` + `<h3>`，内容由 JS 写入 `近 {n} 天支出`（初始 `近 7 天支出`；选 30 时 `近 30 天支出`；选 90 时仍写 `近 90 天支出`）。
- 右侧三枚分段按钮，标签依次为 `7天`、`30天`、`三个月`（对应 value 7/30/90）。
- 选中态：绿底白字绿边；未选中：卡片底+灰字+灰边。默认 7 天。
- 点击任一按钮 → 更新 `trendRange` 并**全量重渲染**（会同时重算表格等）。

**数据口径**
- 横轴：最近 n 天，逐日一个数据点，坐标为**本地日期**；点 i 的日期 = 今天 − (n−1−i) 天（i 从 0 起），即最后一根柱子是今天。
- 纵轴：该日**支出金额之和**，即 `sum(amount where date == 当天 且 type !== "income")`。**收入不计入、也不做正负抵消**。
- 聚合粒度：按天求和（不按周/月聚合）。
- 横轴标签格式 `M/D`（月/日，不补零，例如 `7/5`）。
- 注意：趋势图**不随月份选择器/明细筛选变化**，只随 `trendRange` 与全部账目变化。

**绘制细节（canvas）**
- DOM 属性尺寸 `width=700 height=230`；CSS 实际显示 `width:100%; height:220px; margin-top:18px`；≤560px 时高度 190px。
- 自适应：每次绘制时读取 `canvas.clientWidth`（为 0 时回退 700），按 `devicePixelRatio` 放大位图并 `ctx.scale(dpr,dpr)`；绘制逻辑坐标空间为宽 × **220**（高度硬编码 220，与 DOM 属性 230 不一致，重写时按 220 逻辑高即可）。
- 布局常量：左右边距各 30px；可用宽 `usable = w − 60`；柱宽 `barWidth = min(34, max(4, usable/(n*2)))`；柱间距 `gap = (usable − barWidth*n)/(n+1)`；柱 i 的左边 `left = 30 + gap + i*(barWidth+gap)`。
- 网格：4 条水平线，y = 20、68、116、164，x 从 30 到 w−30，颜色 `--line`，线宽 1px。**没有 Y 轴数值刻度**。
- 基线 y = 174；柱高 `bh = max(4, value/max*150)`，即最高柱 150px；柱顶圆角 5px、底部圆角 2px；颜色固定 `#23805e`（绿色，不随主题变）。
- `max = Math.max(所有日值…, 1)`（全 0 时为 1，所有柱子都是 4px 最小高度）。
- 横轴标签：10px 字体（字族 `Microsoft YaHei`），颜色 `--muted`，居中于柱宽中线，y = 198。
  - 标签抽稀：n=7 → 每 1 个都标；n=30 → 每 5 个标一个（i%5==0）；n=90 → 每 14 个标一个。
- 数值标签：仅当该日 `value > 0` 且 `value/max > 0.2` 时，在柱顶上方 6px 居中绘制 `Math.round(value)` 整数（无货币符号），颜色 `--muted`，10px。
- **空数据表现**：仍然绘制 4 条网格线与全部最小高度柱（4px），无任何数值标签，无“暂无数据”文字提示。
- 重绘时机：初始化、切换档位、窗口 resize（resize 触发整体重渲染）。

### 2.2 环形图（donut）+ 分类占比列表

**统计口径**
- 数据范围 = **月份选择器所选月份**（与趋势图不同，也不受日期范围/类型/分类/搜索筛选影响）。

- 金额为 0 的分类被剔除；剩余按金额**降序**排序。
- 无任何支出时：`total = 0`。

**环形绘制**
- canvas DOM 属性 `190×190`；CSS 显示 `160×160`（≤560px 时布局变为纵向，宽度自适应容器）。
- 逻辑尺寸固定 190；按 dpr 放大；圆心 `(95,95)`，半径 58，`lineWidth = 28`（描边式圆环，非填充扇形）。
- 起始角 `−π/2`（12 点方向），**顺时针**依次绘制各分类弧段，弧长比例 = 该分类金额 / 支出合计；每段颜色取该分类定义色（见 1.1 表）；线段端点为默认平头（butt）。
- 中心文字（仅在有数据时绘制）：
  - 第一行：粗体 20px，颜色 `--text`，内容 = **参与绘制的分类个数**（数字）；
  - 第二行：10px，颜色 `--muted`，内容 `个分类`，位于 y=110。
  - 即中心不显示总金额。
- **无数据表现**：用 `--line` 色画一个完整的灰色圆环（同样半径/线宽），**中心不显示任何文字**，分类列表为空（无占位文案）。

**分类列表（右侧，占剩余宽度）**

- 行间距 12px，字号 11px；小标题 `CATEGORY MIX` + `<h3>分类占比</h3>`（无额外控件）。

### 3.3 日记编辑器

**日期选择**
- 位于「DAILY JOURNAL / 每日日记」标题行右侧的日期框（宽 145px），默认今天。
- 变更（`change`）后重渲染：若编辑器当前绑定的日期与新日期不同，则**直接整体替换**编辑器内容为该日已保存内容（HTML 格式用 `innerHTML`，纯文本格式用 `textContent`），并清除记录的插入选区。
- **未保存内容处理**：切换日期会**静默丢弃**当前未保存的编辑（没有脏标记、没有确认提示、没有自动保存）。同一天内的其它重渲染（如窗口 resize）不会覆盖编辑器内容。

**工具栏**
- 按钮 `＋ 插入图片（可多选）`、`＋ 插入视频`（11px、绿字、圆角 8px）。
- 右侧小灰字说明：`图片单张最大 20 MB · MP4、WebM、MOV 视频单个最大 300 MB`。

**编辑器本体**
- `contenteditable` 富文本区（role=textbox，aria-label `日记内容`），最小高 280px、最大高 420px、超出滚动；14px、行高 1.8；底部有 1px 边框与浅色底，聚焦时绿色边框 + 3px 绿色光晕。
- **占位文案**：`记录今天发生的事、感受或想法……`，实现方式是 `:empty::before`（仅当编辑器真为空时显示；一旦有残留的 `<div>` 或 `<br>`，占位就消失，即使视觉上没内容）。
- **支持的格式**：服务端 `JournalSanitizer` 只保留 **`div`、`p`、`br`、`img`、`video`** 五种标签；其它所有标签被剥离（标签本身丢弃，其中的纯文本保留），文本内容与属性值会做 HTML 转义。
  - `<img>` 仅当 `src` 匹配 `/journal-images/{32位十六进制}.{png|jpg|webp|gif}` 时保留，并保留 `alt`（截断到 100 字符，缺省 `日记图片`）。
  - `<video>` 仅当 `src` 匹配 `/journal-videos/{32位十六进制}.{mp4|webm|mov}` 时保留，输出固定带 `controls` 与 `preload="metadata"`。
  - 结论：重写时只需支持“段落 + 换行 + 内嵌图片 + 内嵌视频”，**没有**加粗/斜体/列表/标题/链接/颜色等格式。
- 图片在编辑器内的显示：块级、`max-width:100%`、`max-height:360px`、居中、左右 10px 外边距、圆角 10px、轻投影、`object-fit: contain`。
- 视频在编辑器内的显示：块级、宽 100%、`max-height:360px`、居中、圆角 10px、黑色底、轻投影。

**插入图片**
- 点 `＋ 插入图片（可多选）`：先记录当前光标选区（编辑器在 `keyup`/`mouseup`/`input` 时持续记录选区），再打开系统文件选择（**多选**；accept = `image/png, image/jpeg, image/webp, image/gif`）。
- 本地校验（在**任何上传之前**整批校验，任一不合格则整批取消并清空选择）：
  - 任一文件 MIME 不在 `image/png|image/jpeg|image/webp|image/gif` → Toast `✓ {文件名} 不是支持的图片格式`；
  - 任一文件 > 20 MB → Toast `✓ {文件名} 超过 20 MB`。
- **上传是即时的**：逐个文件读为 data URL，把逗号之后的部分作为 base64 载荷 `POST /api/journal-images {type, data}`；服务端落盘为 `data/journal-images/{uuid32}.{ext}` 并返回 `{url}`。**上传先于日记保存**，若用户最终不保存日记，会产生孤立媒体文件。
- 插入位置：优先插入到记录的选区处（会先 `deleteContents()`，即替换选中内容）；若无有效选区或选区不在编辑器内，则**追加到编辑器末尾**。
- 插入的 DOM 结构：`<div class="journal-image-block"><img src=... alt="{原始文件名}"></div>`，紧随其后再插入一个空 `<div><br></div>`，并把光标放到这个空块内（方便继续打字）。
- 上传期间 `＋ 插入图片（可多选）` 按钮 `disabled`；完成后恢复并清空文件输入。
- 成功 Toast：`✓ 已插入 {n} 张图片，可继续编辑`。
- 失败：`alert("图片上传失败：{错误信息}")`（服务端错误文案见第 5 节）。

**插入视频**
- 点 `＋ 插入视频`：同样先记录选区，再打开文件选择（**单选**；accept = `video/mp4, video/webm, video/quicktime, .mp4, .webm, .mov`）。
- 本地校验：MIME 不在 `video/mp4|video/webm|video/quicktime` → Toast `✓ 仅支持 MP4、WebM 和 MOV 视频`；文件 > 300 MB → Toast `✓ 单个视频最大为 300 MB`。
- 上传：直接把文件作为请求体 `POST /api/journal-videos`，`Content-Type` 用文件的 MIME（服务端据此判断格式，并校验魔数与内容长度）。
- 插入结构：`<div class="journal-video-block"><video src="..." controls preload="metadata"></video></div>` + 一个空 `<div><br></div>`，光标落到空块。位置规则同图片。
- 成功 Toast `✓ 视频已插入，可继续编辑`；失败 `alert("视频上传失败：{错误信息}")`。上传期间按钮 disabled。

**保存日记**
- 右下角按钮 `保存日记`（绿色主按钮）。
- 本地校验：取 `editor.innerHTML.trim()`；同时检查 `textContent.trim()` 非空、存在 `<img>`、存在 `<video>` 三者之一；**都不满足**时 Toast `✓ 请先写下日记内容`，不发请求。
- 请求：`PATCH /api/journals {date: 所选日期, content: innerHTML, format: "html"}`（**永远提交 html 格式**，纯文本仅在读取旧数据时出现）。
- 成功：重新拉取（服务端会把净化后的内容写库，前端不会把净化结果回填到编辑器，因此页面停留在用户原始 DOM 上，直到切换日期或刷新）+ Toast `✓ 日记已保存`。
- 边界：内容只有 `<br>` 时本地校验以为“有文本”以外的判断均为假 → 实际会通过本地校验（`innerHTML.trim()` 非空）但服务端返回 400 `日记内容不能为空`，前端**无提示**。

**日记状态文案**（编辑器下方左侧）

  - 有 → `已保存，可继续编辑`；

- **没有“未保存更改/正在上传”等中间状态**（重写建议补充脏状态与上传进度）。

**删除日记**
- `删除` 按钮：**仅当所选日期存在日记时显示**。
- 点击 → `confirm("确定删除这一天的日记吗？")` → `DELETE /api/journals/{date}` → 清空编辑器日期绑定 → 重新拉取 → Toast `✓ 日记已删除`。

### 5.1 账目校验 `validate(item)` —— 新增/编辑/导入共用

|---|---|---|---|
| `date` | 必须能被 `strptime("%Y-%m-%d")` 解析 | `日期或金额格式无效` | 与金额解析共用一个 try 块；写入时存原始字符串 |

## 6. 重写时的边界与坑（必须决策的点）

1. **收入/支出计数口径不一致**：统计卡「{n} 笔」含收入，金额只算支出；重写时要么保持一致，要么明确改为“支出笔数”。
2. **CSV 往返丢类型**：导出写 `expense/income`，导入只认 `收入`；不修就会把收入变成支出。建议导出写 `收入/支出` 或导入同时接受 `income/expense`。
3. **月度天数口径**：当月用“今天几号”，历史/未来月用整月天数；空月份会得到 `NaN`。
4. **日期范围与月份互斥**：一旦填了任一日期，月份选择器对明细表完全失效（但统计数据仍按月份）。
5. **趋势图不看筛选**、**环形图只看月份**，两者口径不同，重写时不要在 UI 上暗示它们一致。
6. **环形分类列表只显示前 5 名**，无“其他”汇总项。
7. **错误提示缺失**：除 3 处 alert 外，所有失败静默；重写应统一为一个错误 Toast/对话框（新增文案需自拟，例如直接展示服务端 `error` 字段）。
8. **日记未保存内容在切换日期/切换页面时无提示丢弃**；建议加脏标记 + 保存前确认。
9. **媒体即时上传**：不保存日记会留下孤立文件；重写可改为“保存时一并提交”或提供清理。
10. **日记富文本范围极小**（div/p/br/img/video），PySide6 可用 `QTextEdit` 存 HTML，但需自行实现等价净化（否则 Qt 会写入 `span`/`font` 等标签，再经服务端净化后丢失样式）；更稳的做法是自建“段落列表 + 媒体块”模型。
11. **签到允许未来日期**，且标签可取消选择（无标签 + 有心情 是合法状态）。
12. **`localStorage` 只用于记住当前页**，主题与预算在服务端；PySide6 版应用 `QSettings` 或同一 settings 表。
13. **所有成功写操作后整体重渲染**，因此“输入框内容被库里值覆盖”的行为（预算框、心情框）依赖“按日期绑定”的守卫逻辑；重写时需明确何时刷新控件值、何时保留用户正在输入的内容。
14. **趋势图无 Y 轴刻度、无空数据文案**，只有 4 条网格线；环形图无数据时只有一个灰环。
